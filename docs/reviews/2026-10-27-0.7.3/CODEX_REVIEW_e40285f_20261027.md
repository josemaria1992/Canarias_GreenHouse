## Findings

### R402-01 — P1: Stop all does not cancel a scheduled start waiting its turn

**Location:** `src/aquacrop/programs/engine.py:447–450` (also `:527–532`, `:539–541`, `:670–686`).

The new `_resume` cancellations work, but `_turn_wait.clear()` only forgets scheduled requests. Their occurrences are deliberately unclaimed, so the next AUTO tick asks for the same window again and recreates the wait/start.

Independent fake-I/O reproduction: two weekly sectors with the same duty pair; at 62 s Sector 1 is watering and Sector 2 is waiting. Call `stop_all`, then advance 15 s. Sector 2 starts and emits **two new ONs** (valve and pump). No new operator start occurred. This repeats the original stop/restart problem through the newly added queue; the author tests cover paused remainders, not cancellation of turn-waiting scheduled starts.

**Fix:** cancel the actual pending occurrence/cycle, with an audit record, rather than just clearing the view of its wait. Do the same for the asynchronous stop/lease-loss path. Cover weekly, repeat and condition waiting behaviour without silently redefining future schedules or changing mode policy. A current queued start must not spring back after Stop all; establish any genuinely new schedule/mode policy with the owner.

### R402-02 — P1: the form offers flow units the engine counts incorrectly

**Location:** `src/aquacrop/web/type-form.js:40`, `src/aquacrop/programs/engine.py:1602–1617`.

The form explicitly offers `L/h` and `m³/h`. The engine integrates every engineering value as L/min (`rate * seconds / 60`) without normalizing its unit. Matching type/scaling units do not fix the calculation.

Independent fake meter: type and scaling both use **L/h**, rate **600 L/h** (=10 L/min), target **50 L**. The operation ends DONE with `measured_L=50` after only **0.833 L actually flowed** in the simulated interval. `m³/h` introduces a different factor error. The API/form tests use the first/default unit only, so they miss this.

**Fix:** either offer only end-to-end supported units and reject unsupported ones on the server, or normalize compatible units consistently at the measurement/control boundary. Check volume targets, volume caps and no-flow thresholds as well as the displayed unit. Add equivalent physical-flow regressions for each offered unit and refuse incompatible quantities. Do not fix this by changing the label alone.

### R402-03 — P1: a completed litre target still starts the replacement pump

**Location:** `src/aquacrop/programs/engine.py:1589–1598`, `:1564–1566`.

Counting samples during changeover is fixed, but `_changeover_metering` calls `_account` only. It never checks whether the target or equipment volume cap has now been reached. `_replacing` subsequently starts the partner regardless; completion is checked only after replacement finishes.

Independent fake reproduction: use the author's litre rig with an **11 L target**, delayed OFF verification of 20 s, and drop initial OFF commands for 8 s so the still-running failed pump continues supplying measured water. At 16 s into changeover the engine has counted **18.25 L**, yet remains RUNNING in replacement STOPPING. After OFF is verified it sends a fresh **standby ON**, eventually reporting DONE at **19 L**. Some excess is unavoidable while shutdown is unverified; the subsequent replacement start is avoidable.

**Fix:** enforce total-cycle target and volume-cap termination while accounting through changeover. Reaching either must not start a replacement for an already-satisfied target. Continue retrying/verification of all required OFFs through the established stop path. Test residual flow, delayed/dropped OFF and cap crossings, not only zero flow during shutdown.

### R402-04 — P2: a new Button/Switch silently assumes contact polarity

**Location:** `src/aquacrop/web/type-form.js:92`, `:99–110`.

`startFrom` sends built-in template roles through `fromBody`, which marks them `known: true` and chooses `pol: closed` when `inverted` is absent. Pump feedback added through `addStatus` correctly starts unanswered, but the built-in Button/Switch's existing STATE role does not.

**Independently verified in the browser:** choose New type → Button or switch, enter a name, never touch polarity. “Contact closes when active” is already selected; the draft saves successfully. Pure-model execution also returns no problems. This contradicts the owner's requirement and the summary's claim that polarity starts unchosen. A normally-closed float/contact would be interpreted backwards if the assumption survived commissioning.

**Fix:** distinguish editing a stored definition from creating/copying a type from an unconfirmed starting point. Ask explicitly for each newly introduced digital input's polarity; preserve confirmed values when editing existing types. Add Button/Switch and copied-type coverage alongside the existing Pump test. Do not invent physical wiring.

### R402-05 — P2: changing “What it measures” is lost on save/reopen

**Location:** `src/aquacrop/web/type-form.js:309–310`, `:92–93`, `:144–146`.

The selector changes only presentation field `measure`, label and unit. `toBody` deliberately strips `measure`; `fromBody` reconstructs it from the unchanged role key. Independent execution of the actual model: change a new flow reading to Pressure/bar, save and reopen → `{role: 'flow', label: 'Pressure', unit: 'bar', measure: 'flow'}`. The form again says Flow rate, with a pressure unit. This is inconsistent data, not just a missing label.

**Fix:** make every offered measurement choice persist in a representation the existing model/runtime actually understands, or constrain the selector when the role's quantity cannot safely change. Preserve stable existing bindings/history; do not casually rename live role keys. Test the actual selector → draft endpoint → reopened form journey and reject incompatible quantity/unit combinations. Adding an unrelated temperature reading to a Pump must remain supported without turning it into a flow reading.

### R402-06 — P2: readiness can describe the old Overview import after the current design is cleared/edited

**Location:** `src/aquacrop/web/twin-graph.js:177–183`, `:161`; `src/aquacrop/api/twin_app.py:772–778`.

The reconciliation GET rebuilds the **legacy source** proposal, not the current saved graph. `migrationBox` treats any remembered answer as proof that this panel belongs to the current design, even when New design has since been saved. Source-function reproduction with a saved empty graph and prior completed answers returns **`showsReady=true, currentNodes=0`**. Deleting a necessary connection after completing reconciliation has the same stale-source problem: the panel can still promise “Connections complete: ready to simulate.”

**Fix:** bind import-completion state to the actual design revision/digest and validate readiness against that current design. A saved empty/new design must not inherit completion of an earlier import, and subsequent edits must invalidate/recompute its readiness. Keep the source's saved answers for a deliberate future re-import; do not delete them as a workaround. Add resolved-import → New design → save/reload and resolved-import → remove connection → save/reload browser regressions. The existing empty-design tests check canvas/model emptiness but not this reconciliation panel.
